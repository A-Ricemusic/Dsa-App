## Backend and authentication review

All public Convex operations derive ownership from the authenticated identity through `requireOwnerId`; the existing `tokenIdentifier` convention is retained. The identity-keyed profiles table and auth configuration are present. Problem/category writes check document ownership, attempt writes check both attempt and parent access, and category assignments validate the chosen categories. New pagination cursors continue to operate inside owner- or owned-parent-indexed queries. Cleanup functions remain internal and process bounded batches. Public functions have argument and result validators; no schema migration or unbounded collection query was introduced.

The server uses sealed HttpOnly session cookies, Secure cookies for HTTPS, SameSite=Lax, an expiring PKCE flow, state verification, and origin/header checks on authentication POST requests. Session restoration distinguishes an invalid session from a temporary upstream failure. No server credential is intentionally passed through Vite's public configuration; only the Convex URL is explicitly exposed. Existing automated tests cover the server and frontend authentication branches.

The list-loading fix deliberately preserves complete personal-library search and overview calculations. Network, browser memory, and rendering work still grow with library size: bounded database pages are not a substitute for server aggregates or windowed rendering at very large scale. No claim of large-account load testing is made.
